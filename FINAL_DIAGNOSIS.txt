二、可能的失效原因（需要用户确认）
================================================================

原因1: 用户未登录 ⚠️
────────────────────────────────
症状:
  - 输入问题后直接给答案
  - 或显示 "Authentication required" 错误

原因:
  - /api/v1/clarification/check 需要认证
  - 未登录时返回 401
  - 前端捕获401后应该显示错误（不fallback）

检查方法:
  1. 看页面右上角是否显示用户名
  2. F12 → Console → 查找认证错误
  3. F12 → Network → 查看 /clarification/check 返回 401

解决:
  请先登录系统

────────────────────────────────

原因2: 浏览器缓存问题 ⚠️
────────────────────────────────
症状:
  - 修复后行为未改变
  - 代码更新但前端还是旧版本

原因:
  - 浏览器缓存了旧的JS文件
  - 修改未生效

检查方法:
  1. F12 → Network → Disable cache (勾选)
  2. 硬刷新: Ctrl+Shift+R 或 Ctrl+F5

解决:
  清除缓存并硬刷新

────────────────────────────────

原因3: API调用失败但被静默处理 ⚠️
────────────────────────────────
症状:
  - 没有显示澄清UI
  - 也没有显示错误信息
  - 直接给答案

原因:
  - API调用失败（网络错误、500错误等）
  - 被catch块捕获
  - 第275-285行fallback到直接查询

检查方法:
  F12 → Console → 查找:
    "Clarification check failed"
    "Clarification service unavailable, falling back to direct query"

解决:
  检查后端服务是否正常运行

────────────────────────────────

原因4: 问题类型不触发澄清 ⚠️
────────────────────────────────
症状:
  - 使用了错误的测试问题
  - 或问题太详细，被判断为simple_query

会触发澄清的问题:
  ✓ "我想设计一个RAG系统"
  ✓ "帮我设计RAG"
  ✓ "如何搭建RAG"
  ✓ "比较这两个文档"

不会触发的问题:
  ✗ "什么是RAG"  (general_query)
  ✗ "我想搭建一个企业知识库，处理50GB PDF，要求1秒响应"
     (太详细，被判断为simple_query)

解决:
  使用推荐的测试问题
