# Requirements and Code-Ready Brief

Inspect the repository before asking. Ask one to three highest-value questions per round.

Include:

- user/business outcome and primary user;
- current versus desired behavior with examples;
- inputs, outputs, interfaces, scope, and non-goals;
- error, empty, timeout, concurrency, and authorization behavior;
- security, privacy, tenant, accessibility, localization, compatibility, performance;
- acceptance criteria and expected test evidence;
- telemetry, rollout, rollback, assumptions, and unresolved decisions.

Blocking choices change architecture, public behavior, security/data, compatibility, or irreversible actions. Wait for them. For safe reversible choices, state a default and proceed unless rejected.
