测试步骤
================================================================

1. 打开浏览器访问: http://localhost:5173

2. 登录系统
   - 如果还没有账号，先注册

3. 创建新会话
   - 点击 "New Session" 或类似按钮

4. 测试澄清功能
   输入以下任一测试问题：

   【推荐测试 - RAG设计（7轮）】
   "我想设计一个RAG系统"

   预期：系统会依次询问
   - Round 1: 这个 RAG 主要用于什么场景？
   - Round 2: 数据来源是什么类型？
   - Round 3: 预计的数据规模大概有多大？
   - Round 4: 对响应速度有什么要求？

   【其他测试场景】
   "比较这两个文档的差异"          (document_comparison, 5轮)
   "这个产品的价格是多少"          (specific_query, 3轮)
   "什么是机器学习"                (general_query, 不触发澄清)

5. 验证要点
   ✓ 每个问题都应该显示澄清UI组件
   ✓ 用户选择答案后立即显示下一个问题
   ✓ 不会中断或跳回第一个问题
   ✓ 收集完所有信息后开始生成答案
   ✓ 生成的答案应该基于收集的信息

================================================================
调试方法
================================================================

如果遇到问题：

1. 检查后端日志（后端PowerShell窗口）
   - 查找 "NEED_CLARIFICATION" 或错误信息

2. 检查前端日志（浏览器开发者工具 F12 → Console）
   - 查找 "Clarification" 相关的日志
   - 查看网络请求 (Network tab)

3. 验证API调用
   打开开发者工具 → Network → 筛选 "clarification"
   - 应该看到 POST /api/v1/clarification/check
   - 每次回答后应该有一个新的请求
   - 检查 response.action 是否为 "NEED_CLARIFICATION"

4. 检查会话存储
   后端日志应该显示：
   - "Round 1/7", "Round 2/7" 等进度
   - collected_info 应该在累积

================================================================
常见问题
================================================================

Q: 前端显示 "Authentication required" 错误
A: 这是正常的，因为修复后澄清功能需要登录

Q: 只问了一个问题就停止了
A: 检查后端日志，查看是否有错误。可能是：
   - Intent 识别错误
   - 问题被判断为 simple_query
   - 已经达到 max_rounds

Q: 完全没有显示澄清UI
A: 可能原因：
   - 前端没有正确启动
   - API调用失败（检查 Console 和 Network）
   - 问题类型不触发澄清（试试 "我想设计一个RAG系统"）

停止服务
================================================================

方法1: 在各自的 PowerShell 窗口中按 Ctrl+C

方法2: 运行以下命令强制停止：
```powershell
Get-Process | Where-Object {$_.ProcessName -match "node|uvicorn"} | Stop-Process -Force
```
