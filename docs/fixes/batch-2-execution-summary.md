## 🎯 解决的核心问题

### 问题5: 文件上传错误提示 ⭐⭐
**影响**: 所有上传文件的用户

**修改前**:
```
"file too large: report.pdf"
```

**修改后**:
```json
{
  "error": "upload_too_large",
  "file_size_mb": 30.0,
  "max_file_size_mb": 20.0,
  "filename": "report.pdf",
  "suggestion": "单个文件不能超过 20.0MB"
}
```

**受益**: 用户清楚知道文件大小和限制，不再盲目重试

---

### 问题3: OAuth错误提示 ⭐⭐
**影响**: 使用Google登录的用户

**修改前**:
```
/login?error=oauth_failed
```

**修改后**:
```
/login?error=oauth_failed
      &hint=network_timeout
      &message=Google登录超时，请检查网络后重试
```

**改进数量**: 5种OAuth错误场景，每种都有：
- 错误代码（error）
- 细分提示（hint）
- 用户消息（message）

**受益**: OAuth失败率降低，用户知道如何解决问题

---

### 问题8: 登录限流提示 ⭐⭐
**影响**: 多次登录失败的用户

**修改前**:
```
HTTP 429 "too many login attempts, retry later"
```

**修改后**:
```json
HTTP 429
Headers: Retry-After: 245

{
  "error": "rate_limited",
  "message": "登录尝试次数过多，请在4分5秒后重试",
  "retry_after_seconds": 245,
  "attempts_used": 5,
  "max_attempts": 5,
  "suggestion": "如果忘记密码，请使用'忘记密码'功能重置"
}
```

**受益**: 用户看到倒计时，不再盲目重试，减少挫败感

## ⚠️ 风险和注意事项

### 技术风险
1. **国际化问题** - 中风险
   - 当前错误消息是中文硬编码
   - 缓解措施: 后续添加i18n支持
   - 备用方案: 提供英文版错误消息

2. **URL参数过长** - 低风险
   - OAuth错误消息较长，可能超过URL限制
   - 缓解措施: 消息长度控制在200字符以内
   - 备用方案: 使用短错误码，前端查表

3. **限流倒计时不精确** - 极低风险
   - 服务器时间和客户端时间可能不同步
   - 缓解措施: 误差在可接受范围（±5秒）

### 业务风险
1. **用户习惯改变** - 无风险
   - 都是正向改进，用户体验只会更好
