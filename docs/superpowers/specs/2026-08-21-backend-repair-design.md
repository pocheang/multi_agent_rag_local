# QueryMind 后端修复设计

日期：2026-08-21

## 目标

在不增加产品功能、不自动清理真实数据、不改变公开查询业务语义的前提下，修复后端审计中确认的接口、权限、运行时生命周期、数据完整性、异步阻塞和配置问题。

完成后的后端应满足：

- 修改个人资料不会在写入成功后返回 500。
- viewer、analyst 和 admin 按现有 `query:run` 权限使用澄清流程。
- 配置重载只操作一套权威运行时对象，查询、流式响应、健康检查和生命周期读取同一对象。
- 删除提示词时同步删除版本记录；新安装的关系约束与迁移策略明确。
- 生产环境开启签名时必须提供有效密钥；开发环境给出明确警告。
- 同步 SQLite、文件和评估任务不阻塞 FastAPI 事件循环。
- `.env.example` 的变量名与 `Settings` 实际别名一致。
- 内部异常不直接暴露给客户端，内部运维接口具有明确鉴权。

## 非目标

- 不新增产品功能、页面、接口能力或新的存储后端。
- 不执行真实 `app.db`、`querymind.db` 或 Chroma 数据清理。
- 不重建 Chroma 第三方数据库模式。
- 不解决与 QueryMind 无直接依赖关系的 CrewAI 环境冲突。
- 按用户要求不运行 pytest、Vitest 或其他测试套件；只做生产导入、静态检查和临时数据库功能探针。

## 方案选择

### 采用方案：权威模块持有运行时对象，消费者动态读取

`app.api.dependencies` 继续作为现有查询运行时对象的唯一所有者。消费者不再通过 `from ... import query_guard` 等方式复制引用，而是在请求或生命周期执行时从该模块读取当前对象。管理端重载由一个集中函数构建新对象、原子替换引用，并在替换成功后停止旧队列。

选择此方案的原因：

- 沿用现有结构，不增加第二套服务容器。
- 改动小于扩展现有 connector `AppServices`，不会把两类生命周期强行耦合。
- 能直接修复 Python `from module import object` 导致的陈旧引用问题。
- 失败时可以保留旧运行时，不会先停止旧服务再发现新服务构建失败。

未采用方案：

- 原地修改现有 guard/cache/queue 内部字段：这些对象没有统一、安全的重新配置契约。
- 把所有运行时服务并入 connector `AppServices`：边界扩大，涉及更多无关路由，不符合当前冻结范围。

## 修复设计

### 1. 认证与审计一致性

修正个人资料接口的 `_audit()` 调用，完整传递 `action`、`resource_type`、`result`、`user`、`resource_id` 和 `detail`。数据库更新失败仍由现有服务错误处理；审计成功发生在更新结果确认之后。

本次不引入跨 SQLite 连接的分布式事务。接口必须不再因为调用签名错误而产生确定性 500，审计异常仍按现有全局策略处理。

### 2. 澄清权限与会话契约

三个澄清接口统一检查现有 RBAC 权限 `query:run`。`/check` 在访问历史存储前规范化 `session_id`；只有会话不存在、需要自动创建时，才额外检查现有 `session:create` 权限。历史存储继续按当前用户隔离，因此已有会话只在当前用户命名空间内访问。

不新增 `query:execute` 权限，避免维护两个含义相同的权限名。

### 3. 配置重载生命周期

在 `app.api.dependencies` 中提供单一的运行时重载入口：

1. 读取新 Settings。
2. 完整构建新的 query guard、result cache、quota guard 和 shadow queue。
3. 新队列启动成功后，在锁内替换权威引用。
4. 替换完成后停止旧队列。
5. 构建或启动失败时关闭新对象并保留旧对象。

查询请求、流式执行、健康检查和应用 lifespan 改为动态访问权威模块，不再保留导入时副本。配置重载返回的快照来自替换后的对象。

### 4. 数据关系和迁移边界

`PromptStore.delete_prompt()` 在同一 SQLite 事务内先删除该用户、该提示词的版本，再删除模板，避免继续产生孤儿版本。

现有 544 条孤立认证会话、4 条孤立提示词版本、2980 条无哈希审计和 4 条 Chroma 外键违规只记录在报告中。真实数据修复必须经过备份和单独授权；本轮仅在临时数据库验证清理与迁移逻辑。

Chroma 模式属于第三方组件，本轮不修改其表或触发器。

### 5. 签名配置

增加集中安全配置校验：生产环境若 `RESPONSE_SIGNING_ENABLED=true` 且无法解析活动密钥，启动失败并给出不包含密钥内容的错误。开发环境记录警告并允许启动。

`.env.example` 增加签名配置占位说明，不写入真实密钥。现有审计回填继续使用已修复的迁移脚本，但本轮不对真实数据库执行。

### 6. 异步边界

纯同步的 FastAPI 端点改为普通 `def`，让 FastAPI 在线程池中执行：会话元数据的 CRUD/搜索/标签接口，以及同步评估和比较接口。

必须保留 `await` 的澄清路由继续使用 `async def`；其中短同步历史操作保持最小化，明显的 SQLite/文件重任务使用 `asyncio.to_thread`。返回模型和 URL 不变。

### 7. 配置示例与配置字段

将示例键改为 Settings 实际读取的名称：

- `CHROMA_PERSIST_DIR`
- `CORS_ALLOW_ORIGINS`
- `NEO4J_USERNAME`
- `OAUTH_REDIRECT_URI`

为代码已经读取但 Settings 尚未声明的 `SQLITE_BUSY_TIMEOUT_SECONDS`、`CSRF_ENABLED`、`RATE_LIMIT_ENABLED` 增加字段和合理边界。删除或明确标注后端未使用的示例键，防止静默误配置。

### 8. 信息暴露与小型确定性问题

- 基础 `/health` 和 `/ready` 保持公开，避免破坏编排探针。
- `/circuit-breakers`、agent 详细健康、advanced/enhanced config 和 stats 加管理员鉴权。
- `/metrics` 暂时保持公开以兼容现有采集，不在本轮改变部署契约。
- 500 响应使用稳定的通用文本，完整异常只写日志。
- 合并重复的“安全”同义词集合。
- 补齐 `SessionMetadataService` 类型导入。
- 健康版本从 `app.__version__` 读取，消除硬编码漂移。

## 错误处理

- 配置重载采用“先构建、后替换、最后关闭旧对象”，失败不破坏当前服务。
- 数据库写操作保持单连接事务，删除模板和版本必须一起提交或一起回滚。
- 生产签名配置错误在启动阶段失败，不在请求阶段静默降级。
- 对外 500 错误不包含路径、连接串、异常类型或依赖细节；日志保留 traceback。

## 验证

按用户要求不运行测试套件。使用以下功能级验证：

1. 对所有后端 Python 文件执行 AST 解析和目标 Ruff 规则。
2. 在隔离环境变量和临时目录下导入 FastAPI 应用，检查路由重复与鉴权依赖。
3. 直接调用个人资料路由所用审计契约的临时数据库探针。
4. 用临时 SQLite 验证提示词删除不产生孤儿版本。
5. 用对象身份和生命周期探针验证重载后所有消费者读取新运行时，旧队列停止且新队列可关闭。
6. 验证 viewer/analyst 对三个澄清接口使用同一 `query:run` 权限。
7. 验证生产缺少签名密钥时配置校验失败，开发环境只警告。
8. 重新导入应用并核对真实数据库 SHA-256 未变化。

## 交付顺序

1. 确定性接口与权限故障。
2. 运行时配置重载。
3. 数据关系与签名配置。
4. 异步边界、信息暴露和配置示例。
5. 功能级验证与审计报告更新。
