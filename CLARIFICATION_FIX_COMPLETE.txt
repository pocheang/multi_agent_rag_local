一、问题诊断
================================================================

【症状】
路由智能体的多轮澄清功能不工作 - 用户回答第一个澄清问题后，
系统没有继续提出后续问题。

【根本原因】
存储路径不匹配导致会话上下文丢失：

  /api/v1/clarification/check 端点
  ├─ 原本设计：不需要认证，使用匿名存储
  ├─ 存储位置：sessions/anonymous/{session_id}
  └─ 问题：前端发送的是已登录用户的 session_id

  用户实际会话
  ├─ 存储位置：sessions/user_{user_id}/{session_id}
  └─ 结果：两个存储位置完全不同步

【失效路径】
  1. Round 1: API在 anonymous/ 创建新上下文 → 返回第一个问题 ✓
  2. 用户回答，前端调用 /check 传入 field_name + answer
  3. Round 2: API更新 anonymous/ 中的上下文
  4. 但用户实际会话在 user_X/ 目录，之前的上下文丢失 ✗
  5. 系统无法看到已收集的信息，澄清流程中断 ✗

================================================================
二、修复方案
================================================================

【修改文件】
app/api/routes/public/clarification.py

【核心改动】

  Before:
  -------
  @router.post("/check")
  async def check_clarification(
      req: ClarificationCheckRequest,
      request: Request,
  ):
      settings = get_settings()
      history_store = HistoryStore(
          base_dir=settings.sessions_path / "anonymous"  # ← 问题所在
      )

  After:
  ------
  @router.post("/check")
  async def check_clarification(
      req: ClarificationCheckRequest,
      request: Request,
      user: dict[str, Any] = Depends(_require_user),  # ← 添加认证
  ):
      history_store = _history_store_for_user(user)   # ← 使用用户存储

【修复效果】
✓ 澄清上下文保存在用户实际会话中
✓ 多轮澄清上下文正确持久化
✓ 每轮检查都能访问之前收集的信息

六、已知行为
================================================================

【正常行为】
- rag_design: 最多 7 轮澄清
- document_comparison: 最多 5 轮
- specific_query: 最多 3 轮
- general_query: 不触发澄清

【不触发澄清的情况】
1. 问题过于简单 (如"什么是机器学习")
2. 问题已包含足够细节 (如"我想用50GB的PDF文档搭建企业知识库")
3. Intent 无法识别为需要澄清的类型

【容错机制】
- 达到 max_rounds 后强制 CONTINUE
- 澄清API失败时fallback到直接查询
- 认证失败时显示错误提示（不fallback）
