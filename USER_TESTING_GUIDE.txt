如果仍然不工作
================================================================

检查点1: 查看浏览器Console
────────────────────────────────
按F12 → Console标签

✅ 正常情况:
  - 看到 "Clarification check" 相关日志
  - 没有红色错误信息

❌ 异常情况A - 认证错误:
  Error: 401 Unauthorized
  或显示: "Authentication required for advanced features"

  → 解决: 确保已登录

❌ 异常情况B - API错误:
  Error: Failed to fetch
  或 Error: 500 Internal Server Error

  → 解决: 检查后端服务是否正常运行

❌ 异常情况C - Fallback日志:
  "Clarification service unavailable, falling back to direct query"

  → 解决: 说明API调用失败，检查网络和后端

检查点2: 查看Network标签
────────────────────────────────
F12 → Network标签 → 筛选"clarification"

每次输入问题应该看到:
  POST /api/v1/clarification/check
  Status: 200
  Response: {"action": "NEED_CLARIFICATION", ...}

如果看到:
  Status: 401 → 未登录
  Status: 500 → 后端错误
  Status: 404 → 路由未注册

检查点3: 查看后端日志
────────────────────────────────
查看运行uvicorn的PowerShell窗口

✅ 正常情况:
  POST /api/v1/clarification/check - 200 OK

❌ 异常情况:
  - 看到 401/403 错误 → 认证问题
  - 看到 500 错误 → 后端异常
  - 完全没有日志 → 请求未到达后端

================================================================
终极测试: 手动API调用
================================================================

如果UI测试不工作，用curl直接测试API:

1. 先登录获取token:
   curl -X POST http://localhost:8000/auth/login \
     -H "Content-Type: application/json" \
     -d '{"username":"YOUR_USERNAME","password":"YOUR_PASSWORD"}'

2. 复制返回的access_token

3. 测试澄清API:
   curl -X POST http://localhost:8000/api/v1/clarification/check \
     -H "Content-Type: application/json" \
     -H "Authorization: Bearer YOUR_TOKEN" \
     -d '{"question":"我想设计一个RAG系统","session_id":"test123"}'

预期返回:
  {
    "action": "NEED_CLARIFICATION",
    "clarification": {
      "question": "这个 RAG 主要用于什么场景？",
      ...
    },
    ...
  }

如果这个测试成功，说明后端完全正常，问题在前端。
